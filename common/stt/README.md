# Распознавание речи - общий модуль (режим «файл»)

Версия 0.1.0 · 24.10.2026 · Scribe, задание 06, пункт Б. Стандарт: «Единый стандарт программ», 7.1 - общий блок
`common/stt/`. В 0.1.0 в нём только **режим «файл»** (длинная запись); движок, процесс-воркер и потоковый режим
(Interview Coach, диктофон) переедут сюда следующими версиями.

## 1. Зачем

Scribe распознавал файл одним вызовом Whisper по всей записи. На лекции 2 ч 57 мин это значит:
- пик памяти видеокарты 8,4 ГБ (на Mac с 16 ГБ - сбой, если рядом другая модель);
- «Продолжение следует…» 64 раза на тишине и паузах;
- после сбоя - всё сначала.

## 2. Практика

| Что нашли | Источник | Что берём |
|---|---|---|
| Запись режется детектором речи на куски около 30 с строго по паузам («cut & merge»), куски распознаются пачкой. На TED-LIUM - примерно в 12 раз быстрее обычного Whisper, ошибок слов меньше (9,7 % против 10,5 %), меньше выдуманных фраз и повторов на тишине | WhisperX: Bain и др., Interspeech 2023, arXiv 2303.00747 | нарезка Silero VAD (уже есть в программах) → куски до 30 с → пачка |
| Связь «текст прошлого куска → следующий» чаще порождает повторы | там же; `condition_on_previous_text=False` в Scribe и раньше | не используется |
| Говорящие - по всему файлу отдельным проходом, затем по времени к фразам | там же (pyannote) | так и было в Scribe - не меняется |
| Пачка на faster-whisper - `BatchedInferencePipeline` с готовыми кусками (`clip_timestamps`) | faster-whisper 1.1+, документация | Windows / Linux / «На процессоре» |

## 3. Как работает

1. Звук 16 кГц → фразы VAD (программа передаёт их сама: у Scribe - `vad.split_phrases`).
2. `merge_chunks` - фразы в куски до 30 с; граница куска - всегда в паузе.
3. Пачка по 16 кусков - один вызов кодера и декодера модели (`mlx_decoder`, `fw_decoder`).
4. Кусок не дописан (быстрая речь упёрлась в предел 224 токена на кусок) - его хвост уходит в следующую пачку, как
   обычный проход Whisper продолжает с последней отметки времени. Без этого на собрании терялось 0,5 мин речи.
5. Кусок зациклился (сжатие текста > 2,4) - он один распознаётся обычным вызовом с запасными температурами.
6. Тишина (no_speech > 0,6 при низкой уверенности) - кусок пропускается, как в Whisper.
7. Каждый готовый кусок сразу пишется на диск (`Store`). После сбоя или «Остановить» - продолжение с первого не
   готового куска, без вопросов о стыках: куски не пересекаются.

## 4. Продолжение после сбоя

- Папка `<root>/<ключ>/`: `meta.json` (ключ и куски), `done.jsonl` (строка на готовый кусок, запись с `fsync`).
- Ключ (`file_key`) - путь, размер и время изменения файла и настройки (модель, язык, нормализация). Другой ключ
  или другие куски - распознавание сначала.
- Строка, оборванная сбоем, не считается: этот кусок распознаётся заново.
- `saved_share(root, key)` - доля готового для кнопки «Продолжить (готово 64 %)».
- После готового результата программа удаляет папку (`Store.clear`).

## 5. Проверка

`python3 "_общие модули/stt/tests/test_longfile.py"` - без модели, движок подменён, своя временная папка:
- куски до 30 с с границами в паузах;
- порядок и время сегментов, хвост недописанного куска - со своего места;
- зацикленный кусок - запасной вызов, тишина - пропуск;
- остановка после двух пачек → продолжение: текст тот же, что без остановки, готовое заново не распознаётся;
- другие настройки - сначала; оборванная строка не считается;
- разбор отметок времени Whisper: законченный и недописанный ответ.

Проверка до внедрения (A/B) - Scribe, `docs/Приёмка 2.7.md`.

## 6. API

```python
from common.stt import longfile as lf

store = lf.Store(root, lf.file_key(path, model=repo, lang=lang, normalize=True))
segs = lf.transcribe(audio, spans, lf.mlx_decoder(repo, lang),      # в нити MLX
                     fallback=lambda clip: engine.transcribe(clip, model, lang, temperature=lf.FALLBACK_T),
                     batch=16, store=store, prog=prog, cancel=cancel)
store.clear()                                                        # результат сохранён
```

`lf.Cancelled` - остановка (`cancel()` вернул True); готовое остаётся в `store`.
