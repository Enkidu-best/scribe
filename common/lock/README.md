# Очередь видеокарты `.heavy-lock` - общий модуль

Версия 1.2.0 · 24.10.2026 · задание «_Общие модули 01». Стандарт: «Единый стандарт программ», пункты 2.1, 2.4, 2.5, 6.7, 6.10, 6.11, раздел 7 (строка «Очередь моделей»). Эталон поведения окна - Herald 13 (`tts_gui.py`, `do_start`).

Этот файл - **описание**: код (`heavy_lock.py`, `heavy_lock.sh`, `lock_ui/`) делает ровно то, что здесь написано. Изменение поведения - сначала здесь (версия +1, строка в журнале внизу), потом код, потом `scripts/sync_common.sh` во все проекты.

## 1. Зачем

На Mac Андрея (M4, 16 ГБ общей памяти) видеокарта одна на все программы. Две тяжёлые работы одновременно (модель Ollama, распознавание, синтез, обучение) идут медленнее, а при нехватке памяти одна из них падает (ошибка Scribe 23.10: лекция 3 ч упала, пока «Понятный документ» держал qwen). Нужна **одна очередь на все программы**: кто сейчас работает, кто ждёт, кто следующий - и одинаковое окно «Видеокарта занята» в каждой программе.

## 2. Практика (шаг 1а методики)

| Что нашли | Источник | Что берём |
|---|---|---|
| Замок-файл с PID и именем компьютера владельца; брошенный замок снимается, только если **процесс-владелец мёртв** (проверка `kill(pid, 0)`: нет процесса - мёртв, нет прав - жив); снятие - через переименование в своё имя, чтобы два процесса не удалили чужой свежий замок | py-filelock, `SoftFileLock` ([исходник](https://py-filelock.readthedocs.io/en/latest/_modules/filelock/_soft.html)); openlock ([документация](https://openlock.readthedocs.io/en/latest/usage.html), [PyPI](https://pypi.org/project/openlock)) | живой PID вместо возраста; снятие переименованием; честно: номер процесса может повториться (как и у них - не лечим, риск мал) |
| Очередь задач на одну видеокарту: задача ждёт, пока освободится; видно, кто стоит в очереди | GPU Task Spooler `ts` ([GitHub](https://github.com/yao-sh/task-spooler)), [gpuq](https://pypi.org/project/gpuqu/), [GTasker](https://github.com/suffoquer-fang/gtasker) | файлы очереди с временем постановки - видно, кто следующий; без отдельной службы (у нас нет демона, программы самостоятельны) |
| Приоритет и вытеснение: задача с низким приоритетом работает, пока не придёт важная; вытесняется на контрольной точке (checkpoint) и встаёт обратно | Slurm preemption ([док.](https://third-party-mirror.googlesource.com/SchedMD/slurm/+/refs/heads/slurm-2.5/doc/html/preempt.shtml)), Moab PREEMPTOR / PREEMPTEE ([док.](https://docs.adaptivecomputing.com/mwm/6-1-9/Content/topics/optimization/preemption.html)), Kueue - «кооперативное» вытеснение на контрольных точках ([обсуждение](https://github.com/kubernetes-sigs/kueue/issues/477)) | человек = PREEMPTOR, фон = PREEMPTEE; фон сам проверяет очередь на своих контрольных точках и отдаёт замок (кооперативно - убивать чужой процесс нельзя) |
| Замок «на время» (lease) со сроком опасен: владелец, который подвис, думает, что ещё владеет, а срок истёк | Kleppmann о распределённых замках и fencing token (пересказ: [etcd contrib/lock](https://ftp.yandex.ru/mirrors/github/etcd-io/etcd/main/contrib/lock/README.md), [статья](https://sia.hackernoon.com/the-fencing-gap-why-your-distributed-lock-isnt-safe-and-how-to-fix-it)) | **по возрасту замок не снимает никто чужой** (ошибка Herald 21.10); простой 15 минут - это добровольный отказ самого владельца, а не чужое снятие по часам |
| `mkdir` - атомарная операция файловой системы; уже работает во всех наших программах | Interview Coach `coach/lock.py`, LDB / CD `scripts/heavy_lock.sh`, Herald `core/heavylock.py` | оставляем `mkdir .heavy-lock` и формат `owner` - старые копии продолжают понимать новый замок во время перехода |

Почему не `fcntl.flock` / `msvcrt.locking`: замок держится открытым файлом и сам исчезает при смерти процесса - это хорошо, но его не видят старые копии (они смотрят на папку `.heavy-lock`), а shell-скрипты ночных прогонов не могут держать дескриптор между командами. Переход - по одной программе, поэтому совместимость важнее.

## 3. Что лежит на диске

Всё - рядом с папками проектов, в «Разработка ПО» (путь можно заменить, см. 6):

| Путь | Что | Кто пишет |
|---|---|---|
| `.heavy-lock/` | сам замок (папка; создаётся `mkdir` - атомарно) | владелец |
| `.heavy-lock/owner` | одна строка в прежнем формате: `<Программа> <Fri Oct 23 16:31:05 2026> pid <N>` - её читают старые копии | владелец |
| `.heavy-lock/owner.json` | подробно: `program`, `pid`, `what` (что делает), `since` (ISO-время), `who` (`human` - человек из окна, `background` - фон: прогон Claude Code, ночная цепочка), `host`, `version` | владелец |
| `.heavy-lock-queue/<время>-<программа>-<pid>.json` | ожидающий в очереди: те же поля, `since` - когда встал | ожидающий, убирает за собой |
| `.heavy-lock-queue/now-<программа>-<pid>.json` | «запущено сейчас» поверх чужого замка (см. 5.4) | эта программа, убирает за собой |
| `.heavy-lock-queue/journal.log` | журнал: время, событие, программа, PID, кто, что, сколько держал | все |

Ожидающий или «запущенный сейчас» с мёртвым PID не считается и убирается любым, кто читает очередь.

## 4. Состояния

### 4.1. Замок (общий)

| Состояние | Как узнать | Что видит программа |
|---|---|---|
| **свободен** | папки `.heavy-lock` нет | можно брать |
| **занят** | папка есть, PID владельца жив | «Видеокарта занята: …» |
| **брошен** | папка есть, PID владельца мёртв | снимается молча при следующей попытке взять (событие `stale` в журнале) |
| **пишется** | папка есть, `owner` ещё нет и папке < 10 с | считается занятым (владелец как раз пишет файл) |
| **старый без PID** | `owner` без `pid N`, папке > 3 ч | снимается (так было и раньше; новые копии всегда пишут PID) |

### 4.2. Программа (у каждой тяжёлой операции)

```
свободна ──взять──▶ работает (держит замок) ──готово / Остановить──▶ свободна
   │                     │  ▲
   │ замок чужой         │  │ простой 15 мин (человек)      фон: на контрольной точке
   ▼                     ▼  │ / продолжение                 ждёт человек → отдать, встать в очередь
окно «Видеокарта занята»  отпущена по простою ──продолжить──▶ взять (или окно)
   ├─ «Подождать очереди» ──▶ в очереди (видно место) ──замок освободился, мы первые──▶ работает
   │                            └─ «Отмена» ──▶ свободна
   ├─ «Запустить сейчас» ──▶ работает поверх (замок не наш, пометка now-…)
   ├─ «На процессоре» (если программа умеет и это быстро) ──▶ работает без видеокарты, замок не нужен
   └─ «Отмена» ──▶ свободна
```

| Состояние | RU | EN | Цвет |
|---|---|---|---|
| готова | готова | ready | зелёный |
| работает | работает | working | синий |

| ошибка | ошибка | error | красный |

## 5. Правила

5.1. **Владелец - живой процесс.** Замок снимает либо сам владелец, либо любой - но только если PID владельца мёртв. По возрасту живой замок не снимается никогда. Долгая работа (книга, ночной прогон) держит замок сколько нужно.

5.2. **Очередь честная.** Порядок: сначала все **люди** по времени постановки, потом весь **фон** по времени постановки. Взять свободный замок может только тот, перед кем в очереди нет живых ожидающих. Кто берёт без очереди (`try_acquire`), считается вставшим в конец своего класса: человек без очереди обходит только фон, фон без очереди не обходит никого.

5.3. **Человек важнее фона** (стандарт 2.5).
- Фон не берёт свободный замок, пока в очереди ждёт человек (следует из 5.2).
- Фон, держащий замок, на своих контрольных точках вызывает `checkpoint()` (Python) или `heavy_lock.sh yield` (shell): если ждёт человек - отдаёт замок, встаёт в очередь и продолжает, когда снова его получит. Как часто контрольные точки - решает фон (между главами, файлами, шагами; не реже раза в 10 минут).
- Убивать чужой процесс модуль не умеет и не должен.

5.4. **«Запустить сейчас».** Программа работает, не дожидаясь замка; замок остаётся у прежнего владельца. Предупреждение - в самом окне, второе окно не нужно: «Обе программы будут медленнее; если не хватит памяти, одна из них может остановиться с ошибкой». Пока работает поверх, в очереди лежит `now-…` (видно, кто ещё на видеокарте); по окончании - убирается. Шапка: «работает вместе с «…»».

5.5. **Простой 15 минут** (стандарт 2.5). Открытая сессия **человека**, у которой 15 минут не было действий (репетиция без ответов, книга на паузе, диктофон на паузе), отпускает замок сама (событие `idle` в журнале). При продолжении берёт снова: свободно - молча, занято - окно «Видеокарта занята». Что считается действием, решает программа (нажатия, ответы, распознанные фразы) и сообщает модулю `touch()`. Фон простоем не отпускает: у фона нет «паузы», есть контрольные точки.

5.6. **Кто держит: человек или фон.** Программа из окна - `human`. Скрипты, ночные цепочки, прогоны Claude Code - `background`. Переменная `HEAVY_LOCK_WHO=background` переводит в фон и программу с окном (так проверки Claude Code не обходят Андрея в очереди).

5.7. **Замок уже держит тот, кто запустил.** `HEAVY_LOCK_HELD=1` (и прежние `HERALD_HEAVY_LOCK_HELD`, `IC_HEAVY_LOCK_HELD`, `CLEARDOC_HEAVY_LOCK_HELD`, `LDB_HEAVY_LOCK_HELD`) - программа не берёт и не отдаёт замок сама: его держит ночная цепочка, которая её запустила.

5.8. **Нет папки или прав** (установка на Windows, чужая машина) - программа работает без замка и пишет об этом в свой журнал; окно не мешает работе.

## 6. Как пользоваться

### 6.1. Python

```python
from common.lock import heavy_lock as hl

lock = hl.HeavyLock("Scribe", what="расшифровка «лекция.wmv»")    # who=human по умолчанию
if not lock.try_acquire():
    info = hl.status(lock.path)          # кто держит: program, since, what, who
    ...                                  # окно «Видеокарта занята» (lock_ui)
    ok = lock.acquire(cancel=evt, on_wait=lambda info, ahead: ...)   # «Подождать очереди»
    # или lock.run_now()                 # «Запустить сейчас»
try:
    ...                                  # тяжёлая работа; lock.touch() на действиях человека
    if lock.checkpoint(cancel=evt):      # фон: отдал человеку и снова получил
        ...
finally:
    lock.release()
```

- `status(path)` → `Holder` или `None`: `program`, `pid`, `what`, `who`, `since` (datetime), `since_text` («16:31» сегодня, «22.10 16:31» раньше).
- `queue(path)` → список ожидающих в порядке очереди (5.2); `ahead_of(me)` - сколько передо мной.
- `HeavyLock(program, what="", who=None, path=None, idle_after=900, held_env=None, path_env=None, clock=time.monotonic)`; `who=None` - из `HEAVY_LOCK_WHO`, иначе `human`.
- `try_acquire()`, `acquire(cancel, on_wait, wait=None, poll=1.0)`, `run_now()`, `release()`, `touch()`, `idle_check()` (вызывать раз в несколько секунд; `True` - отпустил по простою), `resume()` (после простоя: взять снова, `False` - занято, показать окно), `checkpoint(cancel, on_wait)` (фон), `set_what(text)`.
- Путь: `HEAVY_LOCK=<путь к .heavy-lock>` (проверки - всегда во временной папке, стандарт 6.10); иначе прежняя переменная программы (`path_env`, например `HERALD_HEAVY_LOCK`); иначе папка «Разработка ПО» (ищется вверх по файлу «Очередь проектов.md»); собранная программа (установщик Windows, полная сборка .app) - общая временная папка системы `<temp>/heavy-lock/.heavy-lock` (одна очередь на машину, папка установки не засоряется); иначе `<папка проекта>/..`.

### 6.2. Shell (ночные скрипты)

```
heavy_lock.sh take "Herald" "дообучение F5" [--who human|background] [--wait-min 330] [--pid $$]
heavy_lock.sh release "Herald" [--pid $$]
heavy_lock.sh status                  # кто держит и кто в очереди - по-русски
heavy_lock.sh yield "Herald" [--pid $$]   # контрольная точка фона
heavy_lock.sh run "Herald" "что делаю" -- команда аргументы…   # взять, выполнить, отдать
```

По умолчанию `--who background`, `--pid` - процесс, который вызвал скрипт (`$PPID`): пока он жив, замок его. `take` ждёт в очереди не дольше `--wait-min` (по умолчанию 330 мин, как раньше) и выходит с кодом 75, если не дождался. `run` экспортирует `HEAVY_LOCK_HELD=1`. Скрипт - тонкая обёртка над `heavy_lock.py` (одна логика на Python и shell); нужен `python3` (или `HEAVY_LOCK_PY`).

### 6.3. Окно: `lock_ui`

- `lock_ui/texts.json` - все тексты окна RU / EN (раздел 7), один источник для Python и веба; `lock_ui.texts.t(key, lang, **поля)`, `describe(holder, lang)`, `header_state(...)`.
- `lock_ui/tk_busy.py` - окно для программ на customtkinter (Herald, Scribe, Anonymizer): `ask_busy(root, T, holder, lang="ru", cpu=None, queue=[])` → `"wait"` / `"now"` / `"cpu"` / `None`; `cpu` - `True` (кнопка «На процессоре» без прогноза) или `{"seconds": прогноз на процессоре, "factor": во сколько раз медленнее видеокарты}` - по замеру этой программы на M4 (доп. 21:40); `factor` больше 3 - кнопка не выделена, надпись «На процессоре (очень медленно)» и предупреждение о нагрузке на процессор (`texts.cpu_option`, `SLOW_FACTOR`); `T` - модуль темы программы (`theme.py`: `label`, `button`, цвета) - окно выглядит как остальная программа. Окно модальное, по центру окна программы, Esc и крестик = «Отмена», Enter = «Подождать очереди».
- `lock_ui/web/heavy-lock.js` + `heavy-lock.css` - то же для веб-программ (IC, CD, LKD, LDB): `HeavyLockUI.ask(holder, {lang, cpu, queue})` → Promise с тем же ответом; `HeavyLockUI.headerState(state)`; сервер отдаёт `GET /api/heavy-lock` = `hl.status_json(path, me=...)`. Подключается вместе с первой веб-программой (Interview Coach, шаг 2.2 задания).

## 8. Подключение к программам

Порядок - из задания: Scribe → Interview Coach → Herald → Понятный документ → LKD, LDB, Anonymizer → ночные скрипты. Одна программа за раз, после каждой - проверка и снимок окна «занята».

Копия попадает в проект скриптом `_общие модули/scripts/sync_common.sh <проект>` в `<проект>/common/lock/` (весь модуль с тестами и `VERSION`). Копию в проекте **не править**: правка - в эталоне, затем синхронизация. `sync_common.sh --check` и `scripts/check_common.py` (для `check_repo.py` проектов) предупреждают, если копия отстала или изменена.

### 8.1. Scribe (первый)

## 10. Бюджет памяти - несколько программ одновременно (1.2.0, «_Общие модули 02»)

### 10.1. Зачем и как

На Apple Silicon нет деления видеокарты на доли: macOS сама делит время видеокарты, две программы работают вместе, каждая
медленнее. Настоящее ограничение - общая память (16 ГБ на систему, программы и модели): модель нужна видеокарте целиком,
не хватило - подкачка на диск или падение. Поэтому вместо «одна программа за раз» - **бюджет памяти**: вместе работают
программы, чьи модели вместе помещаются; приоритет решает, кто ждёт. Тот же подход - планировщик Ollama (модели грузятся,
пока помещаются).

### 10.2. Один файл настроек

`«Разработка ПО»/.heavy-lock-settings.json` (рядом с замком; нет файла - значения по умолчанию из `heavy_lock.py`):

| ключ | что | по умолчанию |
|---|---|---|
| `mode` | `mine_first` - «Сначала мои программы»: вместе, если помещается, фон - только если не ждёт человек; `one_at_a_time` - «Только по очереди» (как до 1.2.0); `night` - «Ночь - всё фону»: фон не уступает на контрольной точке | `mine_first` |
| `budget_gb` | сколько памяти отдаём моделям | 13 (16 минус оценка 3 ГБ на систему - уточнить замером) |
| `pause_background` | «Пауза фону»: фон не берёт видеокарту (и свободную тоже), не встаёт рядом и уступает на ближайшей контрольной точке; ждёт, пока паузу не снимут (1.3.0; в 1.2.0 уступал и тут же брал снова) | `false` |
| `needs_gb` | пиковая память тяжёлой операции программы: `{"Herald": {"gb": 6, "measured": true}}` | оценки, `measured: false` |

**Безопасность до замера.** Вместе запускаются только операции, чья память известна: заявлена самой операцией
(`HeavyLock(..., need_gb=…)`, `heavy_lock.sh run … --need-gb N`) или **замерена** (`measured: true` в таблице). По оценке
рядом никто не встаёт - поведение как до 1.2.0. Так неверная оценка не уронит программу Андрея (Scribe 23.10 упал рядом с
qwen). Таблица заполняется замером (раздел 1 задания 02) - при свободной видеокарте.

### 10.3. Правила

- `try_acquire` / `acquire`: замок свободен - взять, как раньше (если рядом уже работают - только если помещается). Замок
  занят - **встать рядом самому** («join»), если режим позволяет и `занято + моё ≤ budget_gb`; иначе - очередь и окно
  «Видеокарта занята» (2.4). Встал рядом - `joined`, в окне - «работает вместе с «…»» (как «Запустить сейчас»).
- Люди раньше фона: фон встаёт рядом, только если человек не ждёт; ждёт человек и не помещается - фон уступает на
  контрольной точке (`checkpoint`), кроме режима «Ночь».
- Старые копии (до 1.2.0) видят владельца и «работающих рядом» как обычно; их память - по таблице (по имени программы).

### 10.4. Фон - с пониженным приоритетом

`heavy_lock.sh run --who background` запускает команду через `taskpolicy -b` (macOS; Linux - `nice -n 10`): процессор и
диск уступают программе Андрея. Влияние на видеокарту не обещано - замерить. Выключить - `HEAVY_LOCK_NICE=0`. Модели
Ollama фона после работы выгружать (`keep_alive: 0`) - это делает программа.

### 10.5. Где это видно

`heavy_lock.sh gpu` - режим, «занято N из M ГБ», кто работает (сколько памяти, заявлено / замер / не замерено), кто
ждёт. `heavy_lock.sh mode mine_first|one_at_a_time|night`, `heavy_lock.sh pause-bg on|off`. В `status_json` (веб-окна) -
`mode`, `budget_gb`, `used_gb`, `pause_background`, у каждой записи - `off`, `gb`, `gb_how`. Страница «Видеокарта» -
раздел 12.

### 10.6. Проверки

`tests/test_budget.py` - B1-B10: по оценке рядом не встают; замерено и помещается - вместе; не помещается - ждёт; «Только по
очереди»; фон после людей и «Пауза фону»; контрольная точка в режимах; свободный замок, но рядом нет места; командная строка;
пониженный приоритет фона; старая копия-владелец. Каждое правило отключалось - тест падал. Проверка на живых программах
(Herald + Scribe, Herald + «Понятный документ» с qwen3.5:9b и qwen3:14b) - после замера, при свободной видеокарте.

## 11. Чего нет и почему

- **Нет службы-диспетчера** (и в 1.2.0 - бюджет считает каждый по тем же файлам). Программы самостоятельны (отдельные репозитории и сборки Windows); очередь - файлы, читает каждый.
- **Нет снятия чужого живого замка** - ни по возрасту, ни кнопкой. «Запустить сейчас» работает поверх.
- **Нет защиты от повтора номера процесса** (как в py-filelock вне Windows): после перезагрузки Mac брошенный замок с номером, который занял чужой процесс, будет считаться живым. Признак - в «status» владелец, которого нет; снять - `heavy_lock.sh status` покажет, удалить папку руками. Риск мал: замки живут минуты-часы.
- **Старые копии не знают очереди** - до подключения программы она может взять свободный замок мимо ждущего. Уходит по мере подключения.

## 12. Страница «Видеокарта» (1.3.0, «_Общие модули 02», раздел 3)

Одна страница на все программы: `_Программы - быстрый запуск/Видеокарта.app` (ярлык на `tools/Видеокарта.app`).
Запускает `tools/gpu_page.py` - маленький сервер только для этого компьютера (127.0.0.1, порт 8050, занят - любой
свободный; уже открыта - показывает ту же), системный `python3`, без сторонних пакетов. Страница открывается в браузере
по умолчанию, обновляется раз в 2 с; закрыли вкладку - сервер выходит через 10 минут.

| Блок | Что показывает / делает |
|---|---|
| Память | «Занято N из M ГБ» и полоса; память не всех известна - «неизвестно» |
| Работают | владелец и работающие рядом: программа, что делает, с какого времени, вы / фон, память (заявлено / замер / не замерена) |
| Ждут | очередь в порядке очереди |
| «Отпустить» / «Вернуть» | только у фона: отпущенный фон отдаёт видеокарту на ближайшей контрольной точке и не берёт её, пока не «Вернуть»; очередь другим не загораживает. Отметка - файл `off-<pid>` в папке очереди; процесс завершился - снимается. Командная строка: `heavy_lock.sh let-go PID`, `heavy_lock.sh back PID` |
| Режим | три карточки (раздел 10.2) |
| «Пауза фону» | переключатель (раздел 10.2) |

Работу человека страница не останавливает - её отпускают в окне её программы (снятия чужого живого замка нет,
раздел 11). Команда фона без контрольных точек (`heavy_lock.sh run …` без `yield` внутри) отдаёт видеокарту, когда
закончит - так и написано на странице. Изменение режима и кнопки принимаются только со своей страницы (заголовок
`Origin`): чужой сайт в браузере их не нажмёт.

Каркас - по стандарту интерфейса, кроме меню слева (один экран - не применимо): RU|EN, тема (системная / светлая /
тёмная), «Aa» (120 % по умолчанию), версия модуля внизу. Проверка - `tests/test_gpu_page.py` (безголовый Chromium, свой
сервер и замок): что видно, режим / пауза / «Отпустить» / «Вернуть» меняют настройки, чужой `Origin` - 403, в EN нет
кириллицы, контраст axe-core в светлой и тёмной теме - 0 нарушений.
