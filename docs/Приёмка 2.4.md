# Приёмка Scribe 2.4 - Windows и Linux

Задание: `docs/03. Задание для Claude Code - Scribe 2.4 (Windows и Linux).md`. Дата: 15.10.2026.
Все замеры и снимки сделаны на тестовом наборе из `tests/` (синтезированная речь). Личных записей
здесь нет.

**Коротко.**
- **Mac не изменился.** Тексты 2.4 совпадают с 2.3 слово в слово, вместе с таймкодами, на всех
  записях режима «Несколько». Решения «Авто» те же на всех 8 записях. Время то же: разница в
  пределах шума, ±0,2 с на файл. Голосовой ввод LKD работает через воркер Scribe по прежнему
  протоколу.
- **Linux (Docker, процессор).** Качество то же, что на Mac: фраз на верном языке столько же
  на всех 12 прогонах, WER отличается не больше чем на 1,5 п. п., решения «Авто» совпали. Время
  другое: одноязычная запись идёт около 13 мин на час записи (на Mac - 3-4), смешанная - 53-146 мин.
- **Windows.** Установщик `Scribe-Setup-2.4.exe` собирается на GitHub Actions. Там же он ставится
  тихо, расшифровывает тестовую запись из командной строки и удаляется - всё зелёное. **Окно на
  Windows я не видел** (на сервере нет экрана) - ниже чек-лист для проверки на любом компьютере.
- **Размеры.** Установщик - 375 МБ, программа после установки - 1168 МБ. Офлайн-пакет моделей -
  1712 МБ. Ускорение NVIDIA - отдельная докачка 1,24 ГБ.
- **Честный процессор.** Оценка времени в карточке файла считается по замерам на этом же
  компьютере. У галочки «Определять говорящих» - предупреждение, что на процессоре это намного
  дольше. Диктофон сам переходит на модель Small, если текст отстаёт от речи больше чем на 5 с.

## 1. Слой «движок распознавания» (`engine.py`)

Один интерфейс, две реализации:

| | MLXEngine | FWEngine |
|---|---|---|
| где | Mac на Apple Silicon | Windows, Linux, Mac Intel |
| библиотека | mlx-whisper (вызовы - ровно прежние, из 2.3) | faster-whisper (CTranslate2) |
| устройство | видеоядро | NVIDIA (float16), иначе процессор (int8); ошибка CUDA - сам переходит на процессор |
| модели | `mlx-community/whisper-large-v3-turbo` и т. д. | `mobiuslabsgmbh/faster-whisper-large-v3-turbo`, `Systran/faster-whisper-base` и т. д. |

Методы: `transcribe(audio, model, lang, prompt, temperature)`, `transcribe_text` (диктофон),
`detect_language(clips, model)` и `lid()` (определение языка фраз для «Авто» и «Несколько»),
`warmup`, `unload`. Выбор - `engine.get_engine()`, у пользователя выбора нет. В Настройках только
справочная строка «Распознавание: Apple MLX (видеоядро)» / «NVIDIA (видеокарта)» / «процессор -
медленнее»; в боковом меню - «локально на Apple MLX / на видеокарте NVIDIA / на процессоре».
Для проверок есть переменные окружения `SCRIBE_ENGINE=mlx|fw` и `SCRIBE_DEVICE=cpu|cuda`.

«Авто», «Несколько» и диктофон идут только через этот слой. Ветвлений по системе в остальном
коде нет. Ядро без окна вынесено в `core.py`, на нём работают окно, `scribe_cli.py` и замеры.

Одно отличие движков, которое влияет на скорость: детектор языка MLX дополняет фразу до 10 с,
а CTranslate2 принимает только полное окно 30 с. Поэтому на процессоре проверка языков в «Авто»
и режим «Несколько» заметно дороже (см. п. 5).

## 2. Процессор без видеокарты

- **Модель по умолчанию** - large-v3-turbo int8 (та же turbo, что на Mac).
- **Оценка времени** в карточке файла - «≈ 20 с на этом компьютере» / «≈ 25 мин на этом
  компьютере». Считается по прошлым расшифровкам на этой машине: отдельно для одного языка и
  для смешанных записей, с определением говорящих и без. Первый файл идёт без оценки.
  ([светлая](img/2.4/06-estimate-light.jpg), [тёмная](img/2.4/06-estimate-dark.jpg))
- **Определение говорящих** - на процессоре под галочкой предупреждение: «На процессоре -
  намного дольше: часовая запись может идти десятки минут».
  ([светлая](img/2.4/03-cpu-diar-light.jpg), [тёмная](img/2.4/03-cpu-diar-dark.jpg))
- **Диктофон.** Замер задержки на 4-ядерных раннерах GitHub, фраза 4 с, медиана из 3:

  | | turbo | medium | small |
  |---|---|---|---|
  | Linux, 4 ядра x86 | 8,9 с | 6,1 с | 2,0 с |
  | Windows, 4 ядра x86 | 11,7 с | 7,7 с | 3,6 с |
  | для сравнения: Mac M4, MLX | 0,85 с | | |

  Текст у всех трёх моделей на этой фразе одинаковый. Medium тоже не укладывается в 5 с,
  поэтому решение такое:
  - если на процессоре текст отстаёт от речи больше чем на 5 с (медиана трёх фраз), диктофон
    сам переходит на Small и пишет «Текст отставал больше 5 с - диктофон перешёл на модель Small
    (быстрее). Вернуть - в Настройках»;
  - модель можно выбрать и вручную («Модель для диктофона» в Настройках, только на процессоре) -
    тогда автоматика не вмешивается;
  - если Small нет на диске и нет интернета, переключения нет, только подсказка. Small (486 МБ)
    в офлайн-пакет не входит: иначе он превысил бы лимит файла GitHub в 2 ГБ.

  Логика проверена на имитации воркера: после трёх отстающих фраз воркер перезапускается с
  Small ровно один раз, неотвеченная фраза не теряется. С настоящим микрофоном на процессоре
  не проверялась.
  ([Настройки на процессоре, светлая](img/2.4/01-cpu-settings-light.jpg), [тёмная](img/2.4/01-cpu-settings-dark.jpg))

## 3. Пути, открытие файлов, канал воркера (`platform_util.py`)

| | Mac | Windows | Linux |
|---|---|---|---|
| настройки | `~/.audio2text.json` (как раньше) | `%LOCALAPPDATA%\Scribe\settings.json` | `~/.config/Scribe/settings.json` |
| журналы | `~/Library/Logs/Scribe` (как раньше) | `%LOCALAPPDATA%\Scribe\Logs` | `~/.local/state/Scribe/log` |
| открыть файл / показать в папке | `open` / `open -R` | `os.startfile` / `explorer /select,` | `xdg-open` / папка в `xdg-open` |
| канал к воркеру диктофона | сокет AF_UNIX | именованный канал AF_PIPE | сокет AF_UNIX |

Пути на Windows и Linux взяты из реального вывода `scribe_cli.py --engine` на раннерах и в
контейнере.

**Протокол `dictaphone_worker.py` не изменился** - те же сообщения `ready / warmed / text / error`,
тот же вход `(audio, lang, prompt)` или `None`. Внутри воркер теперь зовёт `engine`: на Mac это
тот же вызов mlx_whisper.

**Проверка LKD на Mac.** Его собственный класс `kb_desk.asr.Transcriber` (Python LKD, запуск
воркера Scribe как есть) на фразе, синтезированной голосом Milena:

| прогон | время | текст |
|---|---|---|
| 1 (с загрузкой модели) | 4,1 с (загрузка 3,2 с) | «Добрый день. Прошу подготовить проект договора поставки до пятницы.» |
| 2 | 0,9 с (распознавание 0,85 с) | то же |

Движок в ответе - `scribe`, модель `mlx-community/whisper-large-v3-turbo`.

Что ещё пришлось поправить, чтобы окно не было «маковским» на других системах:
- надписи «на этом Mac» / «в Терминале» / `brew install` - на Windows и Linux свои;
- шрифт `.AppleSystemUIFont` → Segoe UI на Windows, DejaVu Sans на Linux;
- курсор-ссылка `pointinghand` есть только в Tk для Mac - на Windows его создание падало бы;
- скачивание библиотек NVIDIA - через сертификаты certifi;
- у оконного `Scribe.exe` нет консоли: вывод (полоска скачивания моделей и т. п.) уходит в
  журнал, иначе программа падала бы;
- вызовы ffmpeg идут с флагом «без окна», чтобы не мигали чёрные окна консоли (сделано, на
  экране Windows не проверено).

6-11 с вместо 0,5-1 с на Mac. На english_accent - 65 с: сито путает английский с акцентом с
украинским, и turbo перепроверяет больше фраз. На процессоре смешанные записи - это часы на час
записи. Окно это честно показывает в оценке времени, но для частой работы со смешанными записями
на Windows/Linux нужна видеокарта NVIDIA.

## 7. Установщик для Windows (раздел 8 задания)

`.github/workflows/release.yml`, `packaging/scribe.spec`, `packaging/scribe.iss`:

1. **PyInstaller, режим «папка»**: `Scribe.exe` (окно) и `scribe-cli.exe` (консоль) с общими
   библиотеками. Диктофон в сборке - тот же `Scribe.exe` с флагом `--dictaphone-worker`.
2. **ffmpeg** внутри: сборка LGPL от BtbN (`ffmpeg-n8.1-latest-win64-lgpl-8.1.zip`), лицензия -
   в папке программы. В README - указание LGPL и ссылка на исходники.
3. **Inno Setup** → `Scribe-Setup-2.4.exe`. Установка для текущего пользователя, без прав
   администратора. Ярлыки в «Пуске» (и на рабочем столе по галочке), удаление через «Программы».
   Языки установщика - русский и английский.
4. **Проверка на раннере**: тихая установка (`/VERYSILENT /CURRENTUSER`) → `scribe-cli.exe --engine`
   → расшифровка синтезированной английской записи установленным `scribe-cli.exe` (97 % слов) →
   тихое удаление, папки программы больше нет. Всё прошло.
   По пути исправлено: собранный `scribe-cli.exe` не учитывал `PYTHONUTF8` и падал на кириллице
   в выводе - теперь вывод всегда в UTF-8.
5. **Релиз** - по тегу `v2.4` установщик сам попадает в GitHub Releases.
6. **Подписи нет** - в README написано про SmartScreen («Подробнее → Выполнить в любом случае»).

**Модели:**
- **с интернетом** - при первом запуске окно «Загрузка моделей»: список, размеры, что уже есть,
  «Скачать ≈ 1,7 ГБ» с полосой прогресса, «Загрузить из папки…», «Позже». То же окно открывается
  из Настроек.
  ([светлая](img/2.4/02-models-light.jpg), [тёмная](img/2.4/02-models-dark.jpg));
- **без интернета** - офлайн-пакет `Scribe-models-2.4.zip` и Настройки → «Загрузить модели из
  папки…». Подходит и папка, в которую Windows «Извлекла всё» архив (с вложенной папкой того же
  имени). Пакет собирается `tools/make_offline_pack.py`. Внутри обычная структура кэша Hugging Face
  без символических ссылок: распаковывается где угодно.
  Проверено: на Mac (без сети и без токена) Scribe находит все три модели и собирает конвейер
  pyannote с диска; в Linux-контейнере без сети весь набор из п. 5 прошёл на моделях из пакета.
- **Silero VAD** уже внутри программы (`assets/models`).

**pyannote/speaker-diarization-community-1 - лицензия CC-BY-4.0** (проверено по карточке модели
на Hugging Face). Она разрешает распространять модель с указанием авторства. На Hugging Face
модель закрыта формой согласия, но это способ доступа, а не условие лицензии. Поэтому модель
**включена** в офлайн-пакет без изменений, авторство и ссылки - в `NOTICE.txt` внутри архива.
С офлайн-пакетом определение говорящих работает без токена.

**NVIDIA.** Установщик один. Если найдена видеокарта NVIDIA (`nvidia-smi`), а библиотек CUDA
нет, в Настройках появляется кнопка «Ускорение на видеокарте NVIDIA - скачать». Она скачивает
официальные пакеты NVIDIA cuBLAS 12.9 (528 МБ) и cuDNN 9.27 (709 МБ) с PyPI, всего 1,24 ГБ, -
больше порога в ~1 ГБ, поэтому это отдельная докачка. После перезапуска faster-whisper работает
на видеокарте, при ошибке CUDA сам возвращается на процессор. **На настоящей видеокарте не
проверено** - негде.

**Итоги (Ollama)** в установщик не входят. Без Ollama галочка «Итоги» неактивна, под ней
подсказка «Нужна Ollama… Как поставить - нажмите здесь». Подсказка и кнопка «Подвести итоги» у
готового файла открывают объяснение: что это, как поставить, ссылка ollama.com/download.

## 8. Чек-лист для Андрея: проверка на настоящей Windows

Окно Scribe на Windows я не видел. Пройдите, пожалуйста, по списку на любом компьютере с
Windows 10/11; на каждый пункт - минута-две.

1. **Установка.** Скачайте `Scribe-Setup-2.4.exe` из релиза v2.4 и запустите. Если появится
   SmartScreen - «Подробнее» → «Выполнить в любом случае». Ожидание: ставится без прав
   администратора, ярлык Scribe в «Пуске».
2. **Первый запуск.** Откроется окно «Загрузка моделей» со списком и размерами. Нажмите
   «Скачать». Ожидание: полоса растёт, в конце окно закрывается само. Без интернета - распакуйте
   `Scribe-models-2.4.zip` и выберите эту папку кнопкой «Загрузить из папки…».
3. **Настройки.** Строка «Распознавание: …». Ожидание: без NVIDIA - «процессор - медленнее» и
   «Модель для диктофона»; с NVIDIA - кнопка «Ускорение на видеокарте NVIDIA», после неё и
   перезапуска - «NVIDIA (видеокарта)».
4. **Расшифровка.** Перетащите в окно короткую запись (1-2 мин), «Авто», Word. Ожидание: шаги
   под шкалой, готовый .docx рядом с записью. Со второго файла в карточке - «≈ … на этом
   компьютере». Кнопка «Открыть» открывает Word, значок папки - Проводник с выделенным файлом.
   Не мигают чёрные окна консоли.
5. **Смешанная запись** (русский с английскими кусками), «Авто». Ожидание: «Найдены русский и
   английский - обработано как смешанная запись», английские фразы - латиницей. На процессоре
   это долго (п. 5) - лучше запись на 1-2 минуты.
6. **Говорящие.** Отметьте «Определять говорящих». На процессоре под галочкой - предупреждение,
   что это намного дольше. Результат - «Спикер 1 / Спикер 2».
7. **Диктофон.** Разрешите микрофон: Параметры → Конфиденциальность → Микрофон → «Разрешить
   классическим приложениям». Говорите минуту-две. Ожидание: текст появляется по фразам; на
   процессоре, если он отстаёт больше 5 с, - сообщение, что диктофон перешёл на Small.
8. **Итоги без Ollama.** Галочка «Итоги» неактивна, под ней «Нужна Ollama… нажмите здесь» →
   объяснение и ссылка на ollama.com. То же - у кнопки «Подвести итоги» готового файла.
9. **Удаление.** «Параметры → Приложения → Scribe → Удалить». Ожидание: папка программы удалена.
   Модели (~1,7 ГБ) остаются в `%USERPROFILE%\.cache\huggingface` - их можно удалить вручную.

Если что-то не так - пришлите снимок окна и файлы из `%LOCALAPPDATA%\Scribe\Logs` (`scribe.log`,
`dictaphone.log`).

## 9. Что не проверено и ограничения

- **Окно на Windows и Linux** не видел. На Mac окно проверено в режиме процессора
  (`SCRIBE_ENGINE=fw`): строка движка, блок «Модель для диктофона», окно «Загрузка моделей»,
  предупреждение у говорящих.
- **Видеокарта NVIDIA** - ни на раннерах, ни здесь её нет. Код (float16, загрузка библиотек,
  возврат на процессор при ошибке) не проверен на железе.
- **Смешанная запись на Windows** - у раннера нет русского голоса для синтеза. Тот же код
  проверен на Linux (CI и Docker).
- **Скорость смешанных записей на процессоре** - 53-146 мин на час записи. Ускорить её можно,
  например, определяя язык фраз на процессоре только ситом whisper-base, но это меняет решения
  по сравнению с Mac. Не делал без вашего решения.
- **Linux как программа** - запуск из venv (README). Ярлыка `.desktop` и службы нет, установщика
  для Linux нет - в задании для Linux его не было.
