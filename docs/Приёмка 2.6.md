# Приёмка Scribe 2.6 - обработка только выбранных файлов

Задание: `docs/05. Задание для Claude Code - Scribe 2.6 (обработка выбранных файлов).md`. Дата: 15.10.2026.
Все проверки и снимки - на тестовом наборе из `tests/` (синтезированная речь), личных записей нет.

**Коротко.**
- **Главная кнопка работает только с выделенными файлами** и говорит, что будет сделано:
  «Расшифровать: lesson.m4a», «Расшифровать выбранные (3)». Ничего не выделено - кнопка неактивна,
  на ней «Выберите файл в списке». Невыбранные файлы остаются со статусом «Ждёт», их настройки не
  меняются.
- **Рядом спокойная кнопка «Все файлы (N)».** Перед запуском вопрос: «Расшифровать все N файлов в
  очереди? У каждого будут его настройки.», кнопки «Расшифровать все» и «Отмена». N - только файлы
  «Ждёт», готовые не считаются.
- **Новые файлы сами не выделяются**, кроме одного случая: список был пуст и добавлен ровно один
  файл - тогда он выделен, и сразу можно нажать «Расшифровать».
- **Во время работы** можно выделить другой файл и нажать «Добавить в очередь» - он обработается
  после текущего. Вторая кнопка в это время - «Остановить».
- **Cmd+A** (на Windows и Linux - Ctrl+A) выделяет все файлы. В поле ввода текста работает как
  обычно, выделяет текст.
- **Проверено через окно в обеих темах**, все сценарии задания: 28 автоматических проверок в
  каждой теме - OK.

## 1. Как устроено

| Пункт задания | Как сделано |
|---|---|
| 1. главная кнопка - выделенные | один выделенный файл - «Расшифровать: lesson.m4a» (длинное имя сокращается до 22 знаков); несколько - «Расшифровать выбранные (3)»; ничего - неактивна, «Выберите файл в списке» |
| 2. «Все файлы (N)» с вопросом | спокойная кнопка рядом; вопрос - своё окно по центру Scribe с кнопками «Расшифровать все» и «Отмена» (Enter / Esc), а не системные «Да / Нет». N - файлы «Ждёт»; когда таких нет, кнопка неактивна |
| 3. новые файлы не выделяются | кроме единственного файла, добавленного в пустой список |
| 4. невыбранные - «Ждёт» | статус файла в списке теперь «Ждёт». Поставленный на обработку - «В очереди», дальше - этапы, «Готово». Настройки ждущих файлов не трогаются. Раньше по окончании пакета такие файлы помечались «Остановлено» - теперь нет |
| 5. «Добавить в очередь» во время работы | обработчик берёт файлы из очереди по одному, пока она не опустеет; во время работы главная кнопка - «Добавить в очередь: english.m4a» / «Добавить в очередь (2)», она дописывает очередь. «Остановить» возвращает не начатые файлы в «Ждёт» |
| 6. Cmd/Ctrl+A | выделить все файлы списка |

Что ещё поменялось по ходу:
- **Щелчок по уже выделенному файлу больше не снимает выделение.** В 2.5 повторный щелчок снимал
  его. С автоматическим выделением единственного файла это сразу ломалось: щёлкнул по своему
  файлу - кнопка погасла. Это нашла проверка через окно. Снять выделение можно через Esc, щелчок
  по пустому месту списка или «Снять выделение».
- **Готовый файл главная кнопка не предлагает.** После обработки файл остаётся выделенным, и
  кнопка показывала бы «Расшифровать: english.m4a» - то есть повтор. Теперь для готового файла на
  ней «Выберите файл в списке». Чтобы расшифровать файл заново, достаточно изменить его настройки:
  он снова встанет в «Ждёт», подсказка об этом - под заголовком панели.
- Строка под шкалой до запуска: «Добавьте файлы, выберите нужные - и нажмите «Расшифровать»».

На снимках 11 метка «В очереди» у выделенного файла почти сливалась с фоном выделения: у них был
один голубой цвет. После снимков она сделана нейтральной, как «Ждёт». Это правка только цвета,
поэтому прогон не повторял.

Первый прогон с распознаванием упал не в Scribe, а в моей обвязке для снимков: вызов AppKit, которым
окно выводится поверх полноэкранного VS Code, совпал с фоновым потоком Scribe. Обвязка исправлена
(AppKit трогается один раз на окно). Второй прогон нашёл проблему со щелчком по выделенному файлу
(п. 1). Третий и четвёртый прошли целиком.

## 3. Что не менялось

Распознавание, «Авто», «Несколько», процессор, диктофон - без изменений. Тексты и время те же, что
в 2.5 (`docs/Приёмка 2.5.md`). Меняется только то, какие файлы и когда отдаются обработчику, и
настройки каждого файла он по-прежнему читает в момент, когда берёт его в работу.
