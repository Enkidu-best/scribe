# Задание для Claude Code - Scribe 2.4: работа на Windows и Linux

Цель: Scribe запускается не только на Mac, но и на рабочем компьютере с Windows и на сервере с Linux - с видеокартой NVIDIA или без неё. На Mac всё остаётся как есть: та же скорость, тот же результат.

## Что сейчас привязано к Mac (разбор дизайн-чата)

| Что | Где | Замена |
|---|---|---|
| распознавание MLX Whisper (только Apple Silicon) | `whisper_gui.py`, `multilang.py`, `dictaphone_worker.py` | **faster-whisper** (CTranslate2): NVIDIA - float16, процессор - int8; та же модель large-v3-turbo |
| `mlx.core.clear_cache()` при выгрузке | `whisper_gui.py` | для faster-whisper - удалить модель + `torch.cuda.empty_cache()` при CUDA |
| `open`, `open -R` (Finder) | `whisper_gui.py` | Windows - `os.startfile` / `explorer /select,`; Linux - `xdg-open` |
| сокет `AF_UNIX` для воркера диктофона | `dictaphone.py` | на Windows - именованный канал (`multiprocessing.connection` умеет `AF_PIPE`) |
| пути `~/Library/Logs/Scribe`, `~/.audio2text.json` | везде | `platformdirs`: свои папки логов и настроек для каждой системы, на Mac пути прежние |
| сборка `.app` (py2app) | `setup.py` | Windows - PyInstaller (.exe), Linux - запуск из venv + .desktop или служба |

Переносимо без изменений: customtkinter, ffmpeg, Silero VAD (ONNX), pyannote (torch: CUDA или процессор), Ollama (итоги), sounddevice.

## Сделать

1. **Слой «движок распознавания».** Один интерфейс (`transcribe(audio, lang, prompt, temperature)`, `detect_language(clip)`, `unload()`) и две реализации: MLX и faster-whisper.
- Выбор автоматически: Apple Silicon - MLX; есть CUDA - faster-whisper на видеокарте; иначе - faster-whisper на процессоре.
- **Выбора движка у пользователя нет** - всё решается автоматически. В Настройках только справочная строка, например «Распознавание: Apple MLX (видеоядро)» или «Распознавание: NVIDIA (видеокарта)» / «процессор - медленнее».
- Режимы «Авто» / «Несколько» / диктофон работают через этот слой, без ветвлений по системе в остальном коде.

2. **Процессор без видеокарты** - честный режим:
- по умолчанию модель large-v3-turbo int8; для диктофона - выбор меньшей модели (small / medium), если задержка выше ~5 с;
- оценка времени в окне - по замеру на этой машине, а не константа с Mac;
- предупреждение, что определение говорящих на процессоре заметно дольше.

3. **Переносимые пути, открытие файлов, канал воркера** - по таблице выше. Протокол `dictaphone_worker.py` для LKD не ломать: сообщения те же, меняется только способ связи. Проверить, что голосовой ввод LKD на Mac работает.

4. **Проверка на Linux** - в Docker на этом Mac (образ Ubuntu, процессор, без окна):
- консольный прогон расшифровки (`tests/`): «Авто», «Русский», «Несколько» на тестовом наборе;
- результат совпадает с Mac по смыслу (доля верного языка фраз, WER), время - записать.

5. **Проверка на Windows** - GitHub Actions `windows-latest` (процессор): установка зависимостей, автотесты нарезки, короткая расшифровка тестовой записи. Окно на Windows проверить не сможешь - записать это в отчёт честно.

6. **Документация** - README: установка на Windows и Linux, что нужно (Python, ffmpeg, при наличии - драйвер NVIDIA и CUDA), ожидаемая скорость по замерам: Mac M4, процессор в Docker, Windows-раннер.

7. **Mac не трогать по качеству:** после правок повторить замеры 2.2-2.3 на Mac - цифры те же.

## 8. Установщик для Windows (.exe)

Цель: человек на Windows скачивает один установщик, ставит в два клика, и программа работает - без Python, без командной строки.

1. **Сборка** - PyInstaller (режим «папка», не один файл: так быстрее запуск и меньше ложных срабатываний антивируса) + установщик Inno Setup (`Scribe-Setup-2.4.exe`): ярлык в меню «Пуск», удаление через «Программы».
2. **Собирать на GitHub Actions** (`windows-latest`) - на Mac собрать .exe для Windows нельзя. Готовый установщик - в GitHub Releases.
3. **ffmpeg** - положить внутрь сборки (лицензия LGPL-сборки, указать в README).
4. **Модели** - два варианта, оба нужны:
   - **обычный** (интернет есть): при первом запуске окно «Загрузка моделей» с прогрессом и размером - Whisper large-v3-turbo (CTranslate2), whisper-base для «Авто», Silero VAD (уже в сборке, маленький), pyannote;
   - **офлайн-пакет** (рабочие компьютеры и серверы часто без интернета): отдельный архив с моделями + в Настройках «Загрузить модели из папки…». Без обращения к интернету вообще.
5. **pyannote и токен Hugging Face.** Модель определения говорящих скачивается только с токеном и согласием с условиями. Проверить лицензию pyannote/speaker-diarization-community-1: можно ли класть её в офлайн-пакет. Если нельзя - в офлайн-пакете её нет, а в окне понятная инструкция, как добавить.
6. **Видеокарта.** Один установщик: если есть NVIDIA и драйвер - использовать её, иначе процессор. Если библиотеки CUDA сильно раздувают установщик (больше ~1 ГБ) - сделать их отдельной докачкой «Ускорение на видеокарте NVIDIA», а не обязательной частью.
7. **Итоги (Ollama)** - не встраивать. Если Ollama не установлена - кнопка «Итоги» объясняет, как поставить, со ссылкой. Остальное работает без неё.
8. **Подпись.** Установщик без цифровой подписи - Windows покажет предупреждение SmartScreen («Подробнее → Выполнить в любом случае»). Написать это в README. Подпись - отдельный вопрос, сейчас не делать.
9. **Проверка:**
   - на раннере GitHub Actions: тихая установка, запуск расшифровки тестового файла из командной строки, удаление;
   - окно на настоящей Windows проверить не сможешь - честно указать в отчёте и дать Андрею короткий чек-лист для проверки на любом Windows-компьютере.
10. Размеры в отчёте: установщик, офлайн-пакет моделей, место после установки.
