# Приёмка Scribe 2.7 - длинные файлы по практике WhisperX, «Продолжить» после сбоя

Задание: `docs/Архив заданий/06. Задание для Claude Code - Scribe 2.7 (длинные файлы без сбоев, одна нить MLX, прогресс всех этапов).md`,
пункт Б (А, В и Г сделаны раньше, 23.10 - см. HANDOFF, раздел 3). Дата: 24.10.2026. Mac M4, 16 ГБ.

Проверка до внедрения - на двух ваших записях из «Загрузок»: лекция 2 ч 57 мин и собрание 54 мин (3 говорящих). Обе
открывались только кодом Scribe, Finder не трогал. Тексты расшифровок - во временной папке сессии, в git и в
проект их нет; здесь - только числа. Видеокарта - под общей очередью, фоном (`HEAVY_LOCK_WHO=background`).

**Коротко.**
- **Внедрено:** файл одного языка теперь распознаётся кусками до 30 с строго по паузам, пачками по 8 - как в
  WhisperX. По правилу задания - только после проверки A/B: новый способ не хуже по словам и говорящим и быстрее.
- **Лекция 2 ч 57 мин:**
  - распознавание 357 с вместо 479 с - на 25 % быстрее;
  - пик памяти видеокарты 3,3 ГБ вместо 8,4 ГБ;
  - «Продолжение следует…» на тишине 1 раз вместо 64;
  - потерянной речи 0,2 мин вместо 1,5 мин.
- **Собрание 54 мин:**
  - распознавание 150 с вместо 165 с;
  - потерянной речи 0 вместо 2 мин: один проход пропускал окна по 30 с целиком - например, на 35:24 «Вот так.» вместо
    30 секунд разговора;
  - говорящие те же: у 99,8 % слов тот же говорящий, что раньше.
- **Сбой или «Остановить»** - у файла кнопка «Продолжить (готово N %)». Распознавание идёт с первого не готового куска,
  без вопросов о стыках. Проверено вживую: процесс упал на 44 %, второй запуск распознал только остаток (90 с). Текст
  совпал с распознаванием без сбоя на 99,4 %.
- Решение записано в «Единый стандарт», 7.1: длинные файлы - режим «файл» общего блока `common/stt`, не своё
  решение Scribe. Эталон - «_общие модули/stt» 0.1.0.

Что ещё нашлось по ходу:
- **Хвост куска.** В пачке быстрая речь упирается в предел 224 токена на кусок 30 с, и конец куска терялся: 0,5 мин на
  собрании. Обычный проход Whisper в этом случае продолжает с последней отметки времени - сделал так же: недописанный
  хвост уходит в следующую пачку. На лекции таких хвостов 14, на собрании 5. Потерянной речи после исправления - 0 на
  собрании.
- **Зациклившийся кусок** (сжатие текста больше 2,4) распознаётся заново один, обычным вызовом с запасными
  температурами. На обеих записях таких не было.
- **Язык в «Авто»** без уверенного ответа проверки языков - по первым 30 с речи, как раньше решал сам Whisper.
- **«Распознавание речи: часть 7 из 309»** - номер куска в строке этапа (задание, В1). Перед этим - «поиск пауз»
  (на 3 ч - около 15 с).
- **«Осталось ~N мин» после продолжения** считается от первой отметки этапа, а не от нуля: иначе при продолжении с 44 %
  время было бы занижено.

## 2. Проверка до внедрения (A/B)

Способы: **А** - как было, один вызов по всему файлу; **Б** - куски по паузам по одному; **В** - куски по паузам
пачками (внедрён). Звук готовится один раз, общий для всех способов. Модель - turbo, язык - русский.
`tests/ab_long.py`, `tests/ab_speakers.py`.

**Лекция 2 ч 57 мин** (речи 114,8 мин, 309 кусков):

| | А, один проход | Б, по одному | В, пачками по 8 |
|---|---|---|---|
| время распознавания | 479 с | 415 с | **357 с** |
| пик памяти видеокарты | 8,4 ГБ | 2,0 ГБ | 3,3 ГБ |
| слов | 13 112 | 13 284 | 13 442 |
| одна фраза 3+ раза подряд | 65 («Продолжение следует…» - 64) | 1 | 1 |
| слов там, где по VAD нет речи | 151 | 7 | 8 |
| речь в провалах текста длиннее 10 с | 1,5 мин | - | 0,2 мин |
| совпадающих слов с А | - | 89,9 % | 89,3 % |

Подготовка звука (ffmpeg с нормализацией громкости) - 280-290 с, одинаково для всех способов.

**Собрание 54 мин** (3 говорящих, речи 49,4 мин, 139 кусков):

| | А | Б | В, пачками по 16 |
|---|---|---|---|
| время распознавания | 165 с | 179-184 с | **150 с** |
| пик памяти | 3,7 ГБ | 2,0 ГБ | 3,7 ГБ |
| слов | 5 135 | 5 354 | 5 363 |
| повторов 3+ подряд | 3 | 1 | 1 |
| слов вне речи | 8 | 1 | 3 |
| речь в провалах текста длиннее 10 с | 2,0 мин | 0 | 0 |
| совпадающих слов с А | - | 94,8 % | 93,7 % |
| чистота фраз по говорящим | 99,1 % | 99,1 % | 99,1 % |
| тот же говорящий, что в А | - | 99,8 % | 99,8 % |

Где А и В расходятся (12 случайных мест на собрании): в основном слова-связки («вот», «ну») и формы слов - то лучше у
одного, то у другого («вставьте» у В вместо «ставьте» у А, «собственно» вместо «в практике собственное»).

**Знакомые термины** (лекция по психиатрии; на записях эталона нет, поэтому - сколько раз термин распознан):
патология 23 / 22, норма 19 / 20, психиатрия 20 / 20, личность 50 / 51, симптом 16 / 16, депрессия 24 / 25,
шизофрения 4 / 5, диагноз 12 / 12 (А / Б). Разницы нет.

**Ошибки слов на записях с эталоном** (`tests/audio`, синтезированная речь): MLX - русская диктовка 4,8 мин: 2,2 % → 1,5 % (16 → 13 с), английская:
1,1 % → 1,1 % (8,0 → 6,7 с); faster-whisper на процессоре - русская диктовка 4,8 мин: 2,7 % → 2,4 % (82 → 62 с), английская: 1,1 % → 1,1 % (35 → 31 с).

**Скорость - честный замер.** Первый прогон В на всей лекции дал 524 с - медленнее А. Причина: он шёл отдельно, после
часа непрерывной работы видеокарты, и вызывал MLX не из его нити. Повтор в одном процессе по очереди, отрывок
лекции 40 мин:

| А | В16 | Б | В8 | В4 | В16 | А |
|---|---|---|---|---|---|---|
| 102 с | 78 с | 88 с | 83 с | 81 с | 95 с | 108 с |

Видеокарта к концу грелась, и оба способа замедлялись, но В всегда быстрее А. Размер пачки почти не влияет (у turbo
основное время - кодер), поэтому взял 8: меньше памяти. Затем вся лекция, А и В подряд в одном процессе - цифры
таблицы выше (479 с / 357 с).

Почему не «в 12 раз», как у WhisperX: там выигрыш - от пачек на видеокарте NVIDIA и от faster-whisper. У turbo на
Apple M4 кодер и так загружает видеокарту целиком, пачка ускоряет мало. Выигрыш Scribe - в том, что тишина и паузы
больше не распознаются и не порождают выдуманных фраз.

## 5. Что не сделано и почему

- **Говорящие** - как было: по всему файлу отдельным проходом pyannote, затем по времени к фразам. WhisperX делает так
  же; менять было нечего.
- **«Несколько» и смешанная запись в «Авто»** - по фразам, как раньше (`multilang.py`): там язык определяется для каждой
  фразы, куски по 30 с смешали бы языки.
- **Продолжение для «Несколько»** - нет: эта ветка не менялась.
- **Окно со «Продолжить» в тёмной теме не снималось снимком:** проверка окна - программная (S9), снимок `08-resume` -
  только если доступен pyobjc.
