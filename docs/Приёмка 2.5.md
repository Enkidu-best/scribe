# Приёмка Scribe 2.5 - настройки для каждого файла

Задание: `docs/04. Задание для Claude Code - Scribe 2.5 (настройки для каждого файла).md`. Дата: 15.10.2026.
Все проверки и снимки сделаны на тестовом наборе из `tests/` (синтезированная речь). Личных записей
здесь нет.

**Коротко.**
- **У каждого файла свои настройки** - язык, формат, говорящие, таймкоды, итоги. На карточке они
  видны строкой: «Несколько · Word», «English · Субтитры».
- **Выделение.** Щелчок по файлу - панель справа показывает его настройки, заголовок «Настройки:
  lesson.m4a». Cmd-щелчок (на Windows и Linux - Ctrl) и Shift-щелчок выделяют несколько файлов.
  Ничего не выделено - «Настройки для новых файлов».
- **Пачка по-прежнему - одной кнопкой.** Новый файл получает последние выбранные настройки, а
  только что добавленные файлы сразу выделены.
- **Проверено через окно**, в обеих темах. Два файла с разным языком и форматом дали два правильных
  результата: смешанный урок - Word, английская запись - субтитры. Формат английского файла был
  изменён, пока обрабатывался первый, - изменение применилось. Настройки файла в работе не
  меняются.
- **Язык выбран вручную** («Русский», «English») - проверки языков нет совсем (дополнение Андрея):
  у такого файла два шага, «Подготовка» и «Распознавание», даже если у соседнего файла «Несколько».
  Предупреждения о втором языке тоже нет. Русская запись на Mac - на 0,5-0,9 с быстрее, на
  процессоре экономия - 6-12 с.
- **Процессор (решение Андрея).** Язык фраз определяет только whisper-base. На тестовом наборе
  доля фраз с верным языком **та же** (разница 0 п. п. на всех 12 прогонах), урок и вставка
  находятся. Смешанные записи идут в 2,5-3,6 раза быстрее, весь набор - 20 мин на час записи
  вместо 49. На Mac и NVIDIA ничего не изменилось: тексты 2.5 на Mac совпадают с 2.4 слово в слово.

## 1. Настройки для каждого файла

### Как устроено

| Пункт задания | Как сделано |
|---|---|
| 1. у каждого файла свои настройки | `Job.opts`: язык, формат, говорящие (и сколько человек), таймкоды, итоги |
| 2. новый файл - текущие настройки | новый файл получает «последние выбранные» (они же запоминаются между запусками). Только что добавленные файлы **сразу выделены**: поменяли язык - это для них, «добавил пачку - нажал одну кнопку» работает как раньше |
| 3. щелчок выделяет файл, панель - его настройки | заголовок «Настройки: lesson.m4a», изменения - только ему. Cmd/Ctrl-щелчок добавляет файл к выделению, Shift-щелчок - диапазон, заголовок «Настройки: 2 файла», изменение - всем выделенным. Повторный щелчок, Esc, щелчок по пустому месту списка или «Снять выделение» - «Настройки для новых файлов» |
| 4. строка настроек на карточке | «Несколько · Word · говорящие · итоги». Говорящие и итоги показаны, только если они действительно будут (есть токен или офлайн-пакет; есть Ollama) |
| 5. во время обработки | у файла в работе панель заблокирована: «Файл уже в работе - не меняется». У остальных настройки меняются. Обработчик читает настройки файла в момент, когда берёт его в работу |
| 6. «Расшифровать» | обрабатывает всю очередь, каждый файл - со своими настройками |

Обязательного подтверждения настроек для каждого файла нет - как и сказано в задании.

Сверх задания:
- если изменить настройки уже готового файла, он снова встаёт в очередь и по кнопке
  «Расшифровать» расшифруется заново (подсказка под заголовком панели);
- изменение в панели становится «последним выбранным» и для новых файлов - как было до 2.5;
- оценка времени в карточке («≈ 50 с на этом компьютере») считается по настройкам этого файла;
- панель настроек прокручивается, если не помещается (маленькое окно, включены и говорящие, и
  итоги). Полоса прокрутки видна только тогда. Раньше в этом случае подсказка у «Итоги» обрезалась.

### Дополнение: язык выбран вручную - без проверки языков

Раньше при «Русском» или «English» Scribe всё равно запускал проверку языков (`probe_languages`).
Она шла внутри шага «Подготовка звука: проверка языков» и была нужна только для предупреждения
«в записи есть английская речь». Теперь (`core.transcribe_auto`, `forced`):
- проверка языков идёт **только в «Авто»**. При ручном языке её нет - ни отдельным шагом, ни внутри
  «Подготовки»; запись сразу распознаётся на выбранном языке;
- предупреждения о втором языке нет - пользователь выбрал язык сам. Подсказка под переключателем
  теперь такая: «Вся запись распознаётся как «Русский», без проверки языков. Если в записи есть и
  другой язык - выберите «Авто» или «Несколько»»;
- шаг «Разбивка на фразы и определение языка» - только в «Несколько» и в «Авто», когда найдены два
  языка.

**Проверка через окно** (обе темы): три файла в одной очереди, у каждого свой язык. Шаги под
шкалой записаны полностью:

| Файл · язык | Шаги под шкалой |
|---|---|
| dictation · **Русский** | Шаг 1 из 2 · Подготовка звука и нормализация громкости → Шаг 2 из 2 · Распознавание речи |
| lesson · Несколько | Шаг 1 из 3 · Подготовка… → Шаг 2 из 3 · Разбивка на фразы и определение языка → Шаг 3 из 3 · Распознавание речи |
| english · Авто | Шаг 1 из 2 · Подготовка… → Подготовка…: **проверка языков** → Шаг 2 из 2 · Распознавание речи |

У русского файла нет ни проверки языков, ни разбивки на фразы, хотя следом в очереди стоит файл с
«Несколько»; предупреждения нет; все три файла готовы.

## 2. Процессор, смешанные записи - решение Андрея

**Что сделано** (`multilang.lite()`). На процессоре (Windows/Linux без NVIDIA) язык фраз определяет
только сито whisper-base:
- **«Несколько»**: язык каждой фразы и двойное распознавание неуверенных фраз - whisper-base. Текст
  по-прежнему пишет turbo.
- **Проверка «Авто»**: фразу второго языка подтверждает само сито, если уверено в нём от 0,7 и
  больше, чем в основном. Перепроверки turbo нет. Основной язык, как и раньше, определяет turbo по
  6 фразам, если сито в нём не уверено, - это защита от английского с акцентом, который сито
  принимает за украинский.
- На Mac (MLX) и NVIDIA - полный способ, без изменений. Для замеров можно включить любой способ
  переменной `SCRIBE_LID=lite|full`.

**Замер**: Linux в Docker на этом Mac (Ubuntu 24.04, 4 ядра, процессор), весь тестовый набор.
Полный способ - замер 2.4, облегчённый - 2.5:

**Условие задания выполнено**: доля фраз с верным языком не хуже полного способа (одинакова на всех
12 прогонах), урок и вставка находятся (вставка - 7/7 фраз), ложных «смешанных» нет. Одноязычные
записи стоят столько же, как и раньше (±1 мин на час - шум).

**Где облегчённый способ слабее.** В дымовом тесте GitHub Actions на Linux смешанная запись
синтезирована роботизированным голосом espeak-ng. Там облегчённый способ дал 62 буквы кириллицы
вместо ~110 у полного: часть русских фраз сито приняло за английские. Запись всё равно определена
как смешанная, тест проходит. На тестовом наборе (голоса macOS, ближе к живой речи) разницы нет.
На живых записях с очень плохим звуком облегчённый способ может ошибаться чаще полного - если
это проявится, путь назад - `SCRIBE_LID=full`.

## 4. Ещё одна правка: скачивание моделей без зависаний

При скачивании моделей через протокол xet (его по умолчанию включает huggingface_hub) загрузка уже
второй раз намертво останавливалась на середине, без ошибки. Первый раз - при сборке офлайн-пакета
для 2.4, второй - в Docker для этого замера, на 916 МБ из 1,7 ГБ. В окне «Загрузка моделей» это
выглядело бы как застывшая полоса. Теперь Scribe скачивает обычным HTTP
(`HF_HUB_DISABLE_XET=1`, `platform_util.py`): та же загрузка прошла за минуты, прерванная
докачивается.
